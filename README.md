# Smart Booking Assistant

AI-администратор для записи клиентов студии косметологии и массажа.

Проект сделан как портфолио-демо по ТЗ `08_Appointment_Booking_Agent_TZ.txt`.

## Что умеет MVP

- Telegram-бот принимает запись клиента.
- Бот показывает услуги и свободные окна.
- Перед созданием записи слот проверяется повторно.
- Двойная запись к одному специалисту на одно время блокируется.
- Клиент может отменить или перенести запись.
- Администратор получает уведомления в Telegram, если настроен чат.
- Есть простая админ-панель.
- Есть база SQLite.
- Есть демо-данные.
- Есть тестовая отправка напоминания.
- Бот не даёт медицинские советы и передаёт спорные вопросы администратору.

## Архитектура

Проект разделён по правилам SOLID:

- `TelegramBot` отвечает только за Telegram.
- `BookingService` отвечает за создание, отмену и перенос записей.
- `SlotService` отвечает за свободные окна.
- `ClientService` отвечает за клиентов.
- `ServiceCatalog` отвечает за услуги.
- `SpecialistService` отвечает за специалистов и расписание.
- `ReminderService` отвечает за напоминания.
- `AdminNotificationService` отвечает за уведомления администратору.
- `IntentService` отвечает за понимание сообщений.
- `LogService` отвечает за логи.

## База данных

Сначала сгенерируйте Prisma-клиент:

```bash
npm run prisma:generate
```

В этой среде Prisma schema engine может падать на Windows без подробного текста ошибки.
Поэтому для портфолио добавлен локальный безопасный способ создать SQLite-таблицы:

```bash
npm run db:setup
```

Затем заполните демо-данные:

```bash
npm run db:seed
```

Демо-данные включают:

- 3 специалистов;
- 6 услуг;
- рабочие часы;
- перерывы;
- блокировку времени;
- тестовых клиентов;
- тестовые записи.

## Админ-панель

После запуска API админка работает через API `/api`.

Секрет входа по умолчанию:

```text
demo-admin-secret
```

В админке есть:

- список записей;
- фильтры по дате, услуге, специалисту и статусу;
- ручное создание записи;
- услуги;
- специалисты;
- создание специалистов;
- включение и выключение специалистов;
- назначение услуг специалистам;
- рабочие часы специалистов;
- перерывы специалистов;
- блокировка времени;
- клиенты;
- настройки;
- логи;
- тестовая отправка напоминания.

## Как проверить основные сценарии

### 1. Новая запись

В Telegram написать:

```text
Хочу завтра вечером на массаж
```

Бот должен:

- определить намерение записи;
- предложить услугу или сразу свободные окна;
- попросить имя и телефон;
- показать итог;
- создать запись после подтверждения.

### 2. Занятый слот

Попробуйте создать две записи на одного специалиста в одно и то же время.

Ожидаемо:

- первая запись создаётся;
- вторая запись не создаётся;
- система пишет понятное сообщение.

### 3. Отмена

В Telegram открыть `Мои записи`, выбрать запись и нажать `Отменить`.

Ожидаемо:

- запись получает статус `canceled`;
- будущие напоминания отменяются;
- администратор получает уведомление, если Telegram-чат настроен.

### 4. Перенос

В Telegram открыть `Мои записи`, выбрать запись и нажать `Перенести`.

Ожидаемо:

- старая запись получает статус `rescheduled`;
- новая запись создаётся;
- история переноса сохраняется.

### 5. Напоминание

В админке открыть настройки и нажать тестовую отправку напоминания.

Ожидаемо:

- ближайшее запланированное напоминание отправляется клиенту;
- статус напоминания меняется.

### 6. Вопрос по цене

Написать:

```text
Сколько стоит чистка лица?
```

Ожидаемо:

- бот отвечает ценой и длительностью из базы.

### 7. Медицинский вопрос

Написать:

```text
Мне стало плохо после процедуры
```

Ожидаемо:

- бот не ставит диагноз;
- бот передаёт вопрос администратору.

## Защита от двойной записи

Перед созданием записи `BookingService` повторно проверяет слот внутри операции создания.

Слот считается занятым, если у того же специалиста уже есть активная запись, которая пересекается по времени.

Также `BookingService` проверяет, что слот вообще можно бронировать:

- специалист делает выбранную услугу;
- время входит в рабочие часы;
- время не попадает в перерыв;
- время не попадает в ручную блокировку;
- время ещё не прошло.

Активные статусы:

- `confirmed`;
- `needs_attention`.

Неактивные статусы:

- `canceled`;
- `rescheduled`;
- `completed`;
- `no_show`.

## Smoke-тест

Для быстрой проверки без запуска сервера:

```bash
npm run test:smoke
```

Он делает три действия:

- создаёт тестовую запись на ближайший свободный слот;
- пробует создать дубль на то же время;
- проверяет, что дубль заблокирован;
- переносит запись на другое свободное окно;
- проверяет назначение услуги тестовому специалисту;
- проверяет, что ручная блокировка скрывает слот из свободных окон;
- отменяет новую тестовую запись.

## Сценарный тест

Для проверки бизнес-сценариев без запуска Telegram и админки:

```bash
npm run test:scenarios
```

Он проверяет:

- обычную отмену;
- позднюю отмену меньше чем за 3 часа;
- смену статусов "пришёл" и "не пришёл";
- вопрос по цене;
- медицинский вопрос;
- жалобу;
- просьбу администратора;
- выключение услуги;
- сохранение состояния диалога;
- изменение настройки адреса;
- тестовую отправку напоминания.
